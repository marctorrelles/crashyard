Crash reporting on your own Cloudflare account

crashyard is an open-source, Sentry-compatible crash, error and log reporter. It runs as one Worker with D1 and R2 that you deploy in a click. Your apps keep the official Sentry SDKs and only change their DSN.

Readable stack traces from the files you already upload

Point sentry-cli, the Xcode build phase, the Gradle plugin or @sentry/vite-plugin at crashyard. It reads dSYMs, R8 mappings, native libraries and source maps with Sentry's own symbolic library, built to WebAssembly.

  • Crashes that came first are read againAnything from the last 30 days that arrived before its files is processed once they're uploaded.
  • Each frame opens its lineOn GitHub or GitLab, at the release's commit. Private repositories need no token.
  • Suspect commitsAn issue lists the commits in its first release that changed a file in its stack. Fixes CRASHYARD-42 in a message resolves it.

Everything a small team uses Sentry for

Issues, releases, logs, traces and monitors in one dashboard, light or dark, on a desktop or a phone.

Issues

Crashes and errors grouped the way Sentry groups them, searchable with Sentry's query syntax.

  • Resolve now or in the next release
  • Regressions flagged when an issue comes back
  • Merge, ignore, assign and add notes
  • Crashes from App Review and TestFlight called out

Releases

What is new, what regressed and what is gone in each release, against the one before.

  • Crash-free sessions and users
  • Adoption over the last 30 days
  • The commits each release shipped

Logs and traces

Sentry logs, searchable by any attribute, grouped, charted and followed live.

  • Jump from a log to the issue in the same trace
  • Transactions by p95, per release
  • The slowest runs with their spans

Monitors

Cron monitors for scheduled jobs and uptime checks for URLs. Each failure opens an incident.

  • Check in from the SDK, sentry-cli or curl
  • Missed and late check-ins caught
  • Response times and 30 days of results

Status pages

Public pages with the uptime checks you choose, from any of your projects, on your own domain.

  • Post incidents, notices and planned maintenance
  • Updates as things change, with the services affected
  • Your own title, logo and brand color

Product analytics from the SDK you already have

Mark a Sentry log as an action and crashyard counts it: what people do, which steps they finish and who comes back. There's no second SDK in your app and no second bill. And because actions and crashes share their users, you see where one causes the other.

  • Funnels that show what brokeOf the people who stopped at a step, see how many hit an error first, and which issue it was.
  • Retention, with and without crashesWeekly cohorts, and how much less often people come back after a crash in their first week.
  • Users only as hashesAn action keeps its user as the same hash its errors have. No IP addresses, no emails.

Actions are logs on the wire, so they share the daily log limit.

Triage from your agent

An MCP server at /mcp lets an agent such as Claude Code read issues, events, logs, traces and releases, and resolve, assign or merge what it finds. A token acts as you and never does more than your role allows.

Performance

Transactions by p95, how each release changed them, and web and mobile vitals.

Dashboards

Charts, numbers and tables from issues, events and logs, or the Crashes template.

Worker runs

Catches Workers that run out of CPU time or memory, which their own SDK never gets to send.

Passkeys

No passwords. Four roles from owner to viewer, invites, recovery codes, and Sign in with GitHub if you want it.

Updates from GitHub releases

crashyard checks for new releases daily and installs one from the dashboard, or every night.

Installable app

Add it to your phone's home screen, with push notifications on iOS 16.4 and later.

Next to Sentry

Forward every event on to Sentry too, so you can compare the two until you switch.

Private by default

No telemetry, no IP addresses. Passwords, tokens and emails are scrubbed before storing.

Moving from Sentry

Import a project's issues with their latest event, counts, status and comments. New events land on the same issues.

Why native crashes need Paid

Turning a stack trace back into code takes more processing time than the free plan's 10 ms a request. crashyard finds which plan your account is on by itself, and the pages that need Paid say so.

Not there yet

  • React Native with Hermes, obfuscated Flutter and Unity with IL2CPP arrive grouped, with raw frames.
  • Profiles and session replays are accepted and dropped.

How it compares

Other projects keep crash reports yourself too. Here's where crashyard differs.

crashyard

One Worker in your Cloudflare account, with no server to run.

  • Everything the Sentry SDK sends
  • Native symbols through sentry-cli
  • Alert routes with quiet hours
  • Uptime checks and incidents
  • Passkeys and an MCP server
Also on Workers

Bicho, Workers Sentinel

Take errors through an API, without performance data, sessions, logs, monitors or alerts.

In containers

GlitchTip, Bugsink, OpenFault

Speak Sentry's protocol too, and need a server and a database that you keep running.

Hosted

FlareLog

Runs on its own servers, and your apps send with its own SDK instead of Sentry's.

Need session replays or profiling? Use Sentry. crashyard can forward every event there while you compare.

Running in about fifteen minutes

The button copies crashyard to your GitHub account, creates the D1 database and the R2 bucket, and deploys. Add a setup code, create your owner passkey, and give each app's SDK its project's DSN.
